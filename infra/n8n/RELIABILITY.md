# 생성·검증·재실행

2026-10-07 반복 실행 중 인용문을 모델이 살짝 바꿔 쓰는 문제와, 같은 기사에 대한 재생성 과금을 막기 위해 구조를 변경했습니다.

## 원문 근거

본문을 코드에서 근거 목록으로 나누고 고유 ID를 부여합니다. 모델은 JSON Schema의 enum에 있는 ID만 선택합니다.
`quote` 문장을 모델에게 재작성시키지 않고, 선택한 ID의 원문 문자열을 코드에서 복원합니다.
기존 응답의 literal quote도 검사할 수 있지만 원문과 다른 문장을 자동으로 근거로 인정하지 않습니다.
이 구조가 주장과 근거의 의미적 일치까지 보장하는 것은 아닙니다. 기존 숫자 검사와 관리자 검수는 유지합니다.
공식 API 동작: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

### 출력 계약과 실제 응답 재생

실행 21은 유효한 근거 ID를 20개 반환했지만 과거 `validEvidence`의 숨겨진 `<= 8` 제한으로 실패했습니다.
실제 인용문은 모두 원문과 일치했습니다. 모델 스키마에 없던 조건을 검증 코드가 추가로 요구하고,
개수 초과도 인용 불일치라고 표시한 구현 오류입니다.

`draft-contract.mjs`가 근거·슬라이드·문구 길이 한도를 정의하고 모델 요청 스키마와 실제 검증이 공유합니다.
근거는 카탈로그와 동일한 최대 200개를 허용합니다. 잘못된 ID, 다른 원문 인용, 빈 배열, 개수 초과는
각각 다른 사유로 거부합니다. 이미지 선택도 검색한 후보 ID와 대체 후보 최대 2개를 스키마에 넣습니다.

`node infra/n8n/replay-validation.mjs <캡처.json>`으로 실제 응답을 수정하지 않고 모든 현재 검증기에 재생할 수 있습니다.
캡처는 `{executionId,state,draft,raw?}` 형식이며 모델 호출 준비의 상태와 실제 모델 응답을 보관합니다.
장문·복수 출처·근거 1/8/9/20/200개, 범위 초과, 없는 출처, 변조된 인용문을 회귀 테스트합니다.

격리 테스트 통과는 실제 모델 출력·외부 사이트·운영 DB를 통과한 자동 실행 성공과 구분합니다.
수동으로 내용을 고쳐 저장한 경우에도 자동 실행이 성공했다고 보고하지 않습니다.

`replay-cached-execution.mjs <실패 실행 ID>`는 보관된 초안을 현재 검증기로 확인만 합니다.
`--continue-images`를 명시하면 별도 비활성 복구 워크플로를 만들어 후속 검색·선택·저장을 재개합니다.
이 작업은 공유 SQLite 사용을 위해 n8n을 중지한 배포 도구 컨테이너에서 실행하고, 완료 후 n8n을 다시 시작합니다.
본문 재생성·이미지 생성은 차단하고 이미지 선택용 텍스트 API만 최대 1회 허용합니다(기존 캐시가 있으면 재사용).
이미 저장된 기사라면 중복 조회 후 종료합니다. 원본 실행·원본 응답은 수정하지 않으며 복구 실행 ID와 결과를 따로 남깁니다.

## 출력 언어

제목·요약·구성 계획·슬라이드 제목/본문/시각 설명에 한국어 지침과 JSON Schema `pattern`을 적용합니다.
준비된 초안의 문구에는 한글이 있어야 하며 히라가나·가타카나 문장이 섞이면 저장 전에 거부합니다.
모델이 일본어 제목과 한국어·일본어 혼합 본문을 반환한 실제 실패를 재현하는 테스트를 포함합니다.
검색어·이미지 생성 프롬프트는 영어를 유지하고 원문 근거 ID는 바꾸지 않습니다.
문자 제약은 의미·번역 품질을 보장하지 않으므로 원문 대조와 관리자 검수를 유지합니다.
실패 응답은 덮어쓰지 않고 보관하며, 검토한 복구 초안은 원본 실행/생성 기록 ID와 함께 별도 기록합니다.

## 중복과 비용

1. 최근 기사 최대 100개의 URL을 `/internal/v1/generation/existing`으로 조회한 뒤 미처리 기사에만 처리 상한을 적용합니다.
   이미 PENDING/APPROVED/DENIED로 저장된 기사는 모델 호출 전에 제외합니다. 수동 실행에서도 동작합니다.
2. 텍스트 모델 호출 전에 `/internal/v1/generation/claim`으로 기사 URL·작업별 호출을 예약합니다.
   DB unique 제약으로 동시 요청 중 하나만 `CALL`을 받습니다.
3. 반환된 원본 응답은 **검증 전에** `/internal/v1/generation/response`로 보관합니다.
   응답이 잘못됐거나 후속 저장이 실패해도 다음 동일 요청은 `REPLAY`로 반환되어 텍스트 API를 다시 호출하지 않습니다.
4. 요청 내용이 달라졌거나 예약 후 결과 저장이 끝나지 않은 경우는 `BLOCKED`입니다.
   시간 경과만으로 유료 호출 권한을 다시 주지 않습니다. 오류 실행과 `generationRecordId`를 확인해 복구합니다.
5. 최종 기사 저장은 기존대로 PENDING입니다. 같은 URL의 다른 내용을 덮어쓰거나 자동 승인하지 않습니다.

`news_generation_record`에는 요청 JSON·응답 JSON이 저장됩니다. API 키는 저장하지 않습니다.
텍스트 작업 `draft`, `image_selection`과 이미지 작업 `image_generation_<assetKey>`를 각각 예약합니다.
생성 이미지는 확보 직후 저장소에 업로드하고 영구 URL·키를 예약 기록에 보관합니다. 후속 단계가 실패해도 동일 이미지 요청은 저장된 URL을 재사용합니다.
API 호출 후 저장 전에 중단되면 자동 재생성하지 않습니다. 원래 실행의 Binary를 [복구 API](../../server/docs/editorial-operations.md)에 업로드할 수 있습니다.
관리자가 수정한 응답은 원본 응답과 별도로 보관하며 변경 사유·버전·작업자를 기록합니다.
응답 캐시와 검수 데이터는 운영 데이터입니다. 캐시를 지우면 해당 기사의 다음 실행에 비용이 다시 발생할 수 있습니다.
자동 정리/자동 예약 해제는 하지 않습니다. 결과가 불확실한 호출은 n8n 실행 이력과 API 응답부터 확인합니다.

## 배포 순서

- 운영 환경은 [Flyway 마이그레이션](../../server/docs/migrations.md)을 적용합니다. 과거 단일 테이블 SQL은 새 운영 배포 절차로 사용하지 않습니다.
- 새 Spring을 먼저 배포하고 세 API를 사용할 수 있게 한 뒤 워크플로 JSON을 배포합니다.
- 세 노드는 기존 `AI_KNOW Ingestion` Credential을 사용합니다. 기존 서버의 동일 API 경로에는 배포 도구가 연결을 이어 줍니다.
- 새로운 n8n 인스턴스라면 해당 Credential을 생성해 수집·이미지·캐시 HTTP 노드에 선택합니다.
- 백엔드에 접근할 수 없으면 모델을 호출하기 전에 실패하도록 구성했습니다.

## 전체 흐름 검증

`verify-generation.mjs`는 실제 n8n 실행 엔진과 격리된 Spring/H2를 사용합니다.
RSS·원문·모델은 기록된 입력으로 대체하며 외부 네트워크와 유료 API를 호출하지 않습니다.

- 원문 → 근거 ID 응답 → 원본 응답 보관 → 전체 검증 → 이미지 미확보 대체 → PENDING 저장
- 같은 기사 재실행 → 원문/모델 호출 없이 정상 종료
- 존재하지 않는 근거 ID → 검수 DB 저장 거부
- 위 실패 재실행 → 저장된 응답 재사용, 모델 노드 실행 없음
- 생성 후 기사 저장 중단 → 재실행 때 응답 캐시 재사용 → PENDING 저장
- Commons + Openverse 검색 → 관련성 선택 → 원출처 확인 실패 시 다음 후보 → 5장 중 4장 이미지·대표 이미지·출처를 포함한 PENDING 저장
- 생성 PNG fixture → 실제 multipart 업로드/캐시 저장 → 기사 저장 장애 → 재실행 시 저장 이미지 URL 재사용, 생성 노드 미호출

저장소 루트에서 별도 터미널로 테스트 서버를 실행한다(Java 21).

```sh
cd server
./gradlew -I ../infra/n8n/integration-server.gradle runWorkflowIntegrationServer
```

그다음 저장소 루트에서 실행한다. Windows PowerShell은 `$PWD/infra/n8n` 대신 절대 경로를 지정할 수 있다.

```sh
docker run --rm --add-host host.docker.internal:host-gateway \
  --tmpfs /home/node/.n8n:uid=1000,gid=1000 \
  --mount type=bind,source="$PWD/infra/n8n",target=/opt/aiknow,readonly \
  --entrypoint node docker.n8n.io/n8nio/n8n:2.42.3 \
  /opt/aiknow/verify-generation.mjs http://host.docker.internal:18081
```

버전 관리된 가상 기사 fixture를 사용하므로 이전 사용자 실행 캡처 파일은 필요 없다.
테스트 종료 후 테스트 서버만 종료한다. 실제 8080 서버와 기존 MySQL/n8n 볼륨은 사용하지 않는다.

격리 테스트 결과는 실제 NAS 접근이나 미래 모델 출력의 내용 품질을 보장하지 않습니다.
NAS 업로드 경로는 [별도 이미지 저장 검증](TRUENAS.md)을 사용합니다.
