# 카드뉴스 이미지 검색

이미지 중심으로 약 80%의 슬라이드(5장이라면 4장)를 구성하도록 초안 지침을 설정합니다.
기사마다 장별 구성은 자유롭게 정하고, 무관한 이미지를 끼워 넣거나 비율 미달로 초안을 실패시키지는 않습니다.
부족한 경우 `LOW_IMAGE_COVERAGE` 경고를 남깁니다. 이미지가 확보되면 첫 이미지를 대표 이미지로도 저장합니다.

## 검색과 선택

- `searchQuery`에 구체적 대상과 자연스러운 주제 이미지를 찾는 영어 검색어를 `|`로 구분합니다.
  예: `content moderation | online communication`. 최대 2개입니다.
- Commons와 Openverse를 각각 검색하고 각 응답의 12개를 검사합니다. 이미지 용도당 최대 48개,
  전체 최대 5개 용도 × 4회 = 20회 검색입니다. 추가 API 키는 현재 필요하지 않습니다.
- 검색원·검색어가 다른 후보를 섞어 용도별 최대 8개를 관련성 검토에 전달합니다.
  설명을 잘라 기존 모델 입력 한도 22,000자를 유지하며, 검색 후보마다 AI를 호출하지 않습니다.
- 모델은 기사 속 실제 대상을 우선하되 관련 작업 환경·장비·주제 사진도 고를 수 있습니다.
  실제 제품이나 사건 사진처럼 오인되는 이미지는 제외합니다. 이 판단은 **제목·설명 메타데이터** 기준이며,
  이미지 픽셀을 직접 검사하는 기능은 아닙니다. 최종 미감과 관련성은 관리자 검수가 필요합니다.
- 용도별 1순위와 대체 후보 최대 2개를 한 번에 선정합니다. 원출처 확인 실패 시 다음 선정 후보를 확인합니다.
  검증한 이미지는 여러 관련 슬라이드가 공유할 수 있습니다.

## 출처와 사용 조건

Commons와 Openverse 검색 결과에서 CC BY 1.0/2.0/2.5/3.0/4.0, CC0, Public Domain Mark를 확인합니다.
제작자 누락, NC/ND/SA, 명시된 추가 제한, 확인 가능한 작은 해상도는 제외합니다.
Openverse에서는 원본 페이지와 이미지 호스트가 확인된 Wikimedia Commons, Flickr, StockSnap, Rawpixel만 사용합니다.
원본 페이지를 다시 읽어 제작자와 라이선스 링크가 확인되어야 저장합니다. 리디렉션은 자동 추적하지 않습니다.
제목·제작자·라이선스·라이선스 URL·원출처 URL을 보존합니다. 출처만 표기하고 임의의 기사 사진을 가져오지는 않습니다.

공식 API 참고: [Openverse API](https://api.openverse.org/v1/),
[MediaWiki Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo).

## 생성과 저장

모든 검색을 마치고 적합한 기존 이미지를 확보하지 못한 경우에만 개념 이미지 생성을 시도합니다.
`allowImageGeneration=true`와 [TrueNAS 저장소 설정](TRUENAS.md)이 필요합니다.
검색 서비스 오류/호출 제한 때문에 검색을 끝내지 못한 경우에는 유료 생성하지 않고 텍스트와 경고를 남깁니다.
생성이 꺼져 있거나 기존 생성 한도(최대 3개)에 도달한 경우에도 해당 장을 텍스트로 보관합니다.
검색한 원본 이미지는 원본 URL을 유지하고, 생성한 이미지는 기존 NAS 업로드 절차를 따릅니다.

기존 검수 데이터는 자동 변경하지 않습니다. 새 기사부터 적용됩니다.
이미 저장된 기사 URL은 기존 중복 검사로 제외되고, 변경된 요청과 과거 캐시가 충돌하면 자동 유료 재호출하지 않습니다.

## 검증·재생성

`node infra/n8n/sync-image-search.mjs`로 helper와 지침 변경을 워크플로 JSON에 반영합니다.
`node --test infra/n8n/image-search.test.mjs`는 검색 범위·라이선스·관련성 선택·생성 분기를 검사합니다.
`verify-generation.mjs`의 격리된 실제 n8n + Spring/H2 검증은 두 검색원, 원출처 후보 교체,
5장 중 4장 이미지와 대표 이미지·출처를 포함한 PENDING 저장을 확인합니다. 유료 API는 사용하지 않습니다.
