# 서버 운영 준비 작업 계획

## 범위

- 운영 대상 미정: Linux x86_64 / Docker Compose를 기본으로 준비한다. 실제 도메인·서버 인증정보가 설정되기 전에는 원격 배포하지 않는다.
- 카카오/Apple 개발자 설정 미준비: 인증 구현·환경변수·앱 연동 명세를 제공하고 실제 제공자 로그인 검증은 설정 이후 진행한다.
- 프론트 앱과 실기기 FCM 검증은 팀원의 앱 준비 이후 진행한다. TrueNAS 실연결도 보류한다.
- 기존 Google 로그인과 세션 쿠키 인증을 유지한다. 제공자 사용자 ID를 요청 본문에서 신뢰하거나 이메일만으로 다른 계정을 자동 병합하지 않는다.
- AI 이론 콘텐츠는 사용자가 미리 생성한다. 서버는 등록·검수·대체 발송을 지원한다.
- 기존 미커밋 n8n/저장소 변경을 포함해 기존 PR #10에 새 커밋 하나로 추가한다. 기존 4개 커밋은 유지하고 최신 develop 변경도 함께 반영한다.

## 구현 순서

1. 운영 Dockerfile/Compose, Nginx HTTPS 프록시, 환경변수 예제와 배포/복구 절차. Caddy는 사용하지 않는다.
2. 버전 관리 DB 마이그레이션: 신규 DB와 기존 개발 스키마 전환을 분리하고 임의 자동 baseline/운영 데이터 초기화를 금지.
3. 카카오/Apple 인증 및 모바일 연동 계약. 필요한 개발자 설정이 없으면 해당 제공자는 비활성화.
4. RSS 중복 제외 후 후보 제한 적용. 유료 기사 처리 상한은 유지.
5. 관리자 초안 편집, 게시글 정정/비공개/복구, 변경 이력과 동시 수정 방지.
6. 실패한 생성 작업 조회/복구와 생성 이미지 재사용으로 중복 과금 방지.
7. 서버/워크플로/인프라 변경 감지 CI, 이미지 빌드 및 환경 보호를 적용한 배포 경로.

## 구현 후 검증

- Java/Node 테스트와 새 인증·검수·캐시·후보 선택 회귀 테스트.
- 격리 MySQL의 신규 스키마 생성 및 기존 스키마 업그레이드, 재실행과 Hibernate validate.
- 운영 Compose 구성 검사 및 로컬 컨테이너 기동/헬스체크.
- 실제 n8n → Spring → 파일 저장 → 검수 대기 DB 저장. 유료 생성 테스트는 최소 호출로 실행하며 fixture 테스트와 구분한다.
- 승인 경계·이론 대체·첫 발송 게시·비공개 후 발송 중단을 통합 검증.
- 실제 NAS, 미설정 소셜 제공자, 모바일 실기기 수신, 원격 배포는 미검증 항목으로 명시한다.

## 구현 및 로컬 검증 결과 (2026-10-07)

- Nginx 운영 Compose, 비루트 Spring 이미지, Flyway V1–V3, 환경 파일 예제와 배포/복구 절차 구현.
- 모바일 ID 토큰 검증·nonce·세션/CSRF 교체, 검수 편집·재검수·비공개/복구·감사 이력 구현.
- RSS는 DB 중복 제외 후 처리 상한을 적용. 텍스트 원본 및 생성 이미지 URL 캐시, 관리자 복구 구현.
- Java 전체 60개 통과 후 비공개 발송 중단 테스트를 추가해 수집/발송 묶음 8개 재검증: 총 61개 사례 통과.
- Node 48개, 실제 n8n 엔진 통합 10개 시나리오 통과. 외부 기사/모델 응답은 fixture이며 유료 API 호출 0회.
- 별도 MySQL 8: 신규 마이그레이션, 기존 스키마 명시적 baseline, 데이터 보존, Hibernate validate 통과.
- 실제 운영 Compose 형태의 임시 컨테이너: HTTPS 200, 내부 API 외부 404, Secure/HttpOnly 세션 쿠키 확인. 임시 localhost 인증서 사용.
- Docker 다단계 빌드, Compose 검사, GitHub Actions actionlint 통과. 원격 Actions 실행 결과는 PR 반영 후 별도 확인.
- 로컬 DB 백업 후 새 Spring과 워크플로 적용. 기존 PENDING 콘텐츠와 Credential 유지, 스케줄 비활성 유지.
- 최신 fetch에서 `origin/feat/iosPublish`의 `ios/` 소스를 확인했다. main/develop에는 아직 없으며 팀원 작업은 이번 PR에 합치지 않는다.
